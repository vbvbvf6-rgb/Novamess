# Nova relay

Это небольшой reverse-proxy для отдельной точки входа в Nova. Пользователь
открывает адрес relay, а relay передаёт запросы на основной Nova. Поддерживаются
страница приложения, API, загрузки файлов, SSE и Socket.IO WebSocket.

Relay намеренно не принимает URL назначения из запроса: он всегда пересылает
только на `NOVA_ORIGIN`, поэтому это не открытый proxy для произвольных сайтов.

## Запуск

Разместите relay отдельно от основного Nova и задайте:

```bash
NOVA_ORIGIN=https://адрес-основного-nova.example PORT=8080 node proxy/server.mjs
```

Или через npm-скрипт из каталога `proxy`:

```bash
NOVA_ORIGIN=https://адрес-основного-nova.example pnpm start
```

`NOVA_ORIGIN` — адрес production Nova, включая `https://`, без логина и пароля.
`PORT` задаёт порт, который предоставляет выбранный хостинг.

После запуска проверка доступности:

```text
https://адрес-relay.example/__proxy/health
```

Должен вернуться JSON `{"ok":true}`. Пользователям нужно давать именно
`https://адрес-relay.example/`.

## Важно

- Для production используйте HTTPS на relay.
- Relay должен быть отдельным публичным сервисом, а не вторым процессом на том
  же адресе и порту, где работает основной Nova.
- Production-сборка Nova должна использовать относительные запросы (не задавайте
  `VITE_API_URL` на адрес основного сервера), иначе браузер будет обращаться к
  origin напрямую и relay не сможет скрыть его.
- Origin должен оставаться доступным relay, даже если он недоступен
  пользователям напрямую.
